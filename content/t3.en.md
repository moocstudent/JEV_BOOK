## Output tokens are the autoregressive tax

An autoregressive model that emits forty tokens runs forty forward passes, each reading the KV cache — its latency scales with output length, and output length depends on how the model feels like phrasing things. A non-autoregressive encoder passes the input through once and reads logits off the last layer — its latency depends only on input length and batch, not at all on how long the answer is, because the answer has no length.

## Where the two curves cross

The gap is not a constant 'seven times faster'; it depends on the input/output ratio:

- **Short input, long output** (a one-line ticket → a paragraph): the gap is widest, exactly where System One models pay off most.
- **Long input, short output** (ten pages → one enum): the two converge, because the encoder must read those ten pages too.

## The constant-memory point

No KV cache has a consequence that gets missed: memory is constant, not growing with the conversation. That makes concurrency planning arithmetic — no long session blows the budget, and the worker count follows directly from throughput (see OP2).

Measured on this GPU-less machine: the English checkpoint answers three questions in one warm forward pass in 976 ms; the multilingual checkpoint answers one 18-option question at a 401 ms median and 447 ms P95, consistent with the vendor's 193-to-464 ms CPU range. Cold starts pollute the mean — a first reading of 4467 ms was corrupted by a concurrent download; the clean re-run is 401.

**Exercise**: measure your own input/output ratio. If output far exceeds input, a System One model saves little; if the reverse, the gain can be an order of magnitude.
