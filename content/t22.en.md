## 216 rows, 18 classes, why it failed

This chapter replays the book's measurement end to end, every number produced on a Windows machine with no GPU. The task: 216 Chinese requirement rows into 18 business modules, label descriptions from the same sheet's sub-module names, using Laya's multilingual checkpoint (Chinese must go there).

@fig t22-case

- **Accuracy 0.505**, against random 0.056 and majority 0.120 — the model did learn, at nine times random.
- **Latency 401 ms median, 447 ms P95**, consistent with the vendor's 193-to-464 ms CPU range.
- **ECE 0.215 as shipped**, and after fitting T=1.65 on the first half, 0.141 on the second — still above 0.1.
- **The threshold table condemned it**: at 0.50, coverage 56.5% and precision 0.623; at 0.95, coverage 20.8% and precision 0.689. Two thirds of coverage gone for 6.6 points.

## Attribution in three classes

- **Model**: the 18 labels land in the `choice:11+` temperature bucket the library itself refuses; the base checkpoint is a foundation to fine-tune, its README reporting 0.362 zero-shot against 0.318 random.
- **Eval set**: only twelve rows per class on average.
- **Task** (the deepest): the labels overlap semantically, and every model hits that wall.

## The value is the attribution method, not the verdict

The same four steps — split into model, eval-set and task causes, and find which is deepest — apply to any failure of your own. What you must learn is to tell a weak model from a task that was never defined clearly.

**Exercise**: if this task had to be made to work, which step would you change? (Hint: merge the overlapping labels first, then fine-tune the typed-decisions checkpoint on your own data, rather than swapping models.)
