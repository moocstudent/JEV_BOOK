## 输出免费,所以真正花钱的是 state

Jev 按输入 token 计费,每百万 $0.042,输出不要钱。这一行定价表比它看上去重要得多,因为它把 LLM 时代养成的一整套节约习惯翻了过来。在按输出计费的世界里,你会尽量少问、尽量让模型少说;在输出免费的世界里,往一个 choice 里多加二十个选项几乎不加钱,在一次请求里多问十个问题也几乎不加钱。

真正花钱的是你送进去多少 state,而 state 在这几种问法之间是共享的。

## 投机式扇出

于是最省钱的用法反而是**投机式扇出**:把这条数据你未来可能需要的所有判断一次性问完,而不是按需分多次调用——因为第二次调用要重新付一遍 state 的钱。

决策台上把两种用法的月度账单算出来:交叉点通常出现得比人们预期的早得多。当 state 很短而问题很多时,一次问完几乎白赚;当 state 很长而你只需要一个判断时,两种用法没差别。

## 扇出救不了的那类需求

有一个边界:当你需要的判断**依赖前一个判断的结果**时,扇出救不了你,那是个真正的多轮问题。规则很简单——所有**互相独立**的判断一次问完,只有真正有依赖的才分多次。

**练习**:把你一条数据上所有可能的判断列出来,标出哪些互相独立。独立的那些,合成一次请求。你会惊讶于有多少判断其实互不依赖。
