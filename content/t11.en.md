## Options compete with the document for tokens

This chapter explains the least intuitive mechanism in these encoder models, and the root cause of collapse on high-cardinality tasks. Options are not neurons on a classification head — the model has no idea which categories you have — they are text spliced into the input sequence.

@fig t11-budget

So the sequence budget splits in two: `head_max_len` for options, `max_len` minus that for the document. The English checkpoint defaults to 512/192, the multilingual to 1024/256. The arithmetic shows the problem: at 18 labels each gets `(256-16)//18 ≈ 13` tokens; at Banking77's 77 labels only three or four remain, the labels become indistinguishable, and accuracy falls to 0.425 where Jev scores 0.870.

## Three remedies

1. Raise `head_max_len` and `max_len` so each option has enough tokens.
2. Use `predict_shortlist` to retrieve a top-k with embeddings, then one forward pass.
3. Split the label set yourself into a coarse question and a fine one.

## A counter-intuitive measurement

On 216 Chinese requirement rows across 18 labels, raising `head_max_len` from 256 to 1024 (about 56 tokens per label) moved **accuracy not at all** — still 0.505 — while P95 latency went from 447 ms to 2290 ms.

The conclusion: token budget is a **necessary but not sufficient** condition for high-cardinality collapse. When the labels themselves overlap semantically, more room cannot save them — then the thing to fix is the taxonomy, not the budget (see EV2).

**Exercise**: compute how many tokens each label keeps at your label count. If it is below your Chinese description length, try raising the budget once; if that does nothing, check whether the labels overlap.
