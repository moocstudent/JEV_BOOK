## One endpoint, two things

Jev's entire API surface is one endpoint: `POST https://api.typesafe.ai/v1/systemone`. The request carries two things — `state`, your program's state as a string, dict or list with no schema to design in advance; and `questions`, a dict whose keys are the answer names you want and whose values declare a `type`, `instructions` and `criteria`.

@fig t4-api

Each answer comes back with its type, result, the full probability distribution and a `confidence`, plus an `{input_tokens, output_tokens}` usage block. That is all of it.

## Two unremarkable but decisive choices

**questions is a dict, not a list**. Your code fetches answers by name rather than index, and reordering questions cannot change behaviour.

**Who reads the criteria key and who reads the description**. For choice, criteria is a key-to-description mapping and the model reads the **description** — the key is only the identifier your program switches on. So keys may be `A`/`B`/`C`, but descriptions must be written properly. This returns throughout the measurements: accuracy produced with label names as descriptions is a floor, not a ceiling.

## How to reach it today

Official early access is queued, while Vercel wired it into the AI Gateway the day after launch, callable from AI SDK 7's `evaluate` method with no waitlist. For local work, point at an open compatible server (see OP1) instead.

**Exercise**: take one 'pick a department / score it / judge yes-no' requirement and hand-write a valid `/v1/systemone` request. Writing the descriptions, you will immediately find that explaining a category is harder than naming it.
