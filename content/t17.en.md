## Lessons from 216 real rows

This chapter builds an evaluation set from the data this book actually used: 216 Chinese requirement rows to be sorted into 18 business modules, with label descriptions taken from each module's own sub-module names in the same sheet — not invented.

@fig t17-dataset

## Four things

**Sample size**: 216 over 18 averages twelve per class, already below the rule that per-class metrics need at least twenty. So this set supports a credible overall accuracy but not credible per-class numbers, and the report must say so.

**Label descriptions**: the model reads descriptions, not keys, so numbers produced with label names as descriptions are a floor, not a ceiling. A concrete method: mine descriptions from structure you already have (sub-modules, synonyms, frequent terms in historical tickets), which is more accurate and faster than writing them fresh.

**Split discipline**: the half you fit the temperature on must not overlap the half you report.

**The taxonomy itself**: the real reason this dataset failed. Warehouse management and material assurance under customer plan changes were never mutually exclusive in the business, and a row about finished-goods stock belongs to both. That overlap is not the model's problem — every model hits the same wall.

## Health-check agreement before modelling

Have people label the same batch twice and compute agreement. A taxonomy below 0.8 is not worth testing a model on — you will mistake a taxonomy problem for a model problem.

**Exercise**: find a colleague, independently label the same 30 rows, and compute agreement. Below 0.8, go fix the label definitions before touching a model.
